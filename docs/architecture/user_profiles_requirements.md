# Профили пользователей

## Функциональные требования

- FR1. Пользователь может получить свои данные профиля: email, ФИО, телефон, таймзона, статус верификации email.
- FR2. Пользователь может отредактировать ФИО и телефон.
- FR3. Пользователь может удалить или деактивировать свой профиль.
- FR4. Администратор с правом доступа к личным данным может искать и просматривать профили пользователей по email/телефону/ФИО.
- FR5. Пользователь видит в профиле список фильмов, добавленных в закладки.
- FR6. Пользователь видит в профиле выставленные им рейтинги фильмов.
- FR7. Пользователь видит в профиле свои рецензии.
- FR8. На странице фильма отображается пользовательский рейтинг и список рецензий (в дополнение к `imdb_rating`).
- FR9. Пользователь может изменить свою таймзону после регистрации.
- FR10. Пользователь может включать/отключать отдельные каналы уведомлений (email/sms/push) или все уведомления целиком.
- FR11. Рассылки персонализируются: в письмо подставляется ФИО получателя.
- FR12. Пользователь получает уведомление, когда кто-то лайкает или дизлайкает его рецензию, в том числе push-каналом.
- FR13. Пользователь может посмотреть список недавно просмотренных фильмов и продолжить просмотр с сохраненной позиции.
- FR14. При входе с указанным телефоном пользователь проходит дополнительный шаг двухфакторной аутентификации.
- FR15. Автор рецензии может выбрать, как отображается его авторство: реальное ФИО, никнейм или анонимно.
- FR16. Пользователям с высоким количеством лайков присваивается звание «топ-рецензент».
- FR17. Доступ к чувствительным данным и операциям проверяется по конкретному permission-коду, а не только по признаку суперпользователя.
- FR18. Пользователь видит в профиле текущую подписку и историю подписок.
- FR19. Пользователь может самостоятельно оформить или проапгрейдить подписку без участия администратора.
- FR20. Оформление подписки проходит через заглушку оплаты: инициация возвращает фиктивный «URL оплаты», отдельный вызов имитирует подтверждение оплаты и активирует подписку.

## Нефункциональные требования

- NFR1. Доступ к персональным данным в админке ограничен ролью/правом, а не общим статусом администратора. Не все админы должны видеть телефон и ФИО пользователей из соображения безопасности.
- NFR2. Эндпоинт с активностью пользователя не должен падать целиком, если недоступен user_actions-service (например, возвращать пустые списки).
- NFR3. Код подтверждения для двухфакторной аутентификации хранится временно (с TTL).
- NFR4. Если для рейтинга/рецензий на странице фильма выбрано асинхронное обновление среднего пользовательского рейтинга фильма и количества рецензий (или лайков/дизлайков) на этот фильм (Kafka + Elasticsearch), допустима задержка обновления данных.
- NFR5. При полном удалении аккаунта данные пользователя в user_actions-service (закладки/рейтинги/рецензии) должны быть удалены каскадно, а не остаться висеть без владельца (целостность данных).
- NFR6. Заглушка оплаты подписки повторяет форму запросов настоящей интеграции, чтобы ее можно было заменить реальным провайдером без изменения контракта API.
- NFR7. Поиск профилей в админке регистронезависим и работает по частичному совпадению.
